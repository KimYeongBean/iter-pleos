# 작업 흐름 (사람 + AI 에이전트)

4명이 각자 에이전트로 작업합니다. 기본 규칙은 [AGENTS.md](../AGENTS.md)와 [CONTRIBUTING.md](../CONTRIBUTING.md)이고, 이 문서는 그 위의 작업 순서입니다.

## 이슈 하나를 처리하는 순서
Addy Osmani agent-skills 흐름을 따릅니다.

1. **spec** — 이슈의 사용자 동작과 완료 조건을 확인합니다. 모듈 경계를 넘으면 [interfaces.md](interfaces.md)부터 봅니다.
2. **plan** — 작은 단계로 나눕니다.
3. **build** — 자기 모듈 안에서 조금씩 구현합니다.
4. **test** — 테스트 또는 재현 방법을 남깁니다.
5. **review** — 다른 사람(또는 다른 에이전트 + 사람)이 리뷰합니다.
6. **ship** — 사람이 승인한 PR로만 merge합니다. 에이전트는 merge하지 않습니다.

## 스킬 사용
- **개인 스킬은 자기 모듈 안에서 자유롭게** 써도 됩니다.
- 특정 스킬 파일을 저장소에 설치할 필요는 없습니다. 각자 로컬에서 해당 스킬을 쓰면 됩니다.
- Matt Pocock 스킬(`grill-me`, `grill-with-docs`, `tdd`)은 **질문·검증 도구**로 씁니다.
  - 김영빈은 인터페이스·스펙 경계(모듈 사이 입출력, 동결 범위)에서 `grill-me` / `grill-with-docs`로 빈틈을 묻습니다.
  - `tdd`는 새 로직과 데이터 변환(예: 주행 데이터 → 그래프 값)에 권장합니다. 모든 UI 스케치에 강제하지는 않습니다.

## 에이전트가 하지 않는 것
사람이 명시적으로 요청하지 않으면:
- 새 공유 문서나 새 폴더 구조를 만들지 않습니다.
- `AGENTS.md`를 다시 쓰지 않습니다.
- 새 용어·모듈 경계를 문서([GLOSSARY.md](../GLOSSARY.md), [interfaces.md](interfaces.md)) 없이 만들지 않습니다.
- 다른 소유자의 모듈 파일을 수정하지 않습니다 ([ownership.md](ownership.md)).

## 완료 기준 (Definition of Done)
- [ ] 이슈에 적힌 사용자 동작이 실제로 됩니다.
- [ ] [interfaces.md](interfaces.md)를 깨지 않습니다. (바꿔야 하면 먼저 합의)
- [ ] PR에 담당 모듈 테스트 또는 재현 방법이 있습니다.
- [ ] 다른 모듈과 함께 빌드·실행됩니다.
- [ ] 작성한 에이전트의 self-review만으로 끝내지 않습니다. 사람 리뷰어 1명 이상이 승인합니다.
